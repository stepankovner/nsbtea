# НСБ Чай — интернет-магазин китайского чая

Сайт nsbtea.ru для магазина «НСБ Чай» (ИП, Владимир). Заменяет бесплатную витрину Точка Банка.
Цель: перевести заказы из личных сообщений и звонков на сайт; главный рычаг продаж — бонусные баллы.
Управлять сайтом будет владелец (не программист) с телефона и ноутбука.

## Документы — читать перед работой

- `docs/SPEC.md` — функциональные требования (главный документ ТЗ)
- `docs/DATA_MODEL.md` — сущности и правила данных
- `docs/ROADMAP.md` — этапы, порядок работ, критерии готовности
- `docs/DESIGN.md` — дизайн; референсы лежат в `docs/design/references/`
- `docs/DECISIONS.md` — журнал решений (вести самостоятельно, см. ниже)

Работаем строго по этапам из `docs/ROADMAP.md`. Фаза 2 не начинается, пока не закрыта фаза 1.

## Стек

- **Backend:** Python 3.12+, FastAPI, SQLAlchemy 2 (async), Alembic, Pydantic v2, PostgreSQL 16, Redis
- **Фоновые задачи и расписание:** arq (воркер на Redis)
- **Telegram-бот:** aiogram 3, работает внутри backend-сервиса (webhook)
- **Frontend:** Next.js (App Router, актуальная стабильная версия), TypeScript strict, Tailwind CSS, shadcn/ui
  - витрина и админка — одно приложение: route groups `(shop)` и `admin`
  - типы API генерируются из OpenAPI FastAPI (`openapi-typescript`), руками не дублируются
- **Файлы:** S3-совместимое хранилище в РФ; картинки при загрузке конвертируются в WebP нескольких размеров
- **Инфраструктура:** Docker Compose, Caddy (HTTPS), VPS в РФ, GitHub Actions (lint, тесты, деплой), Sentry
- **Интеграции:** Точка Банк (интернет-эквайринг + фискализация), СДЭК API v2 + виджет ПВЗ, Telegram Bot API, Яндекс Метрика

## Жёсткие правила

1. **Деньги** — только целые копейки (`int`). Никаких float. Округление цены строки — до целого рубля, half-up.
2. **Вес** — только целые граммы (`int`). Остаток чая хранится в граммах.
3. **Остатки** меняются только через `InventoryMovement` в той же транзакции, что и кэш `stock_grams`/`stock_units`.
   Списание — атомарный `UPDATE ... WHERE stock >= :qty`. Отрицательных остатков быть не может.
4. **Баллы** меняются только через `PointsTransaction` (журнал). Баланс = сумма журнала, кэш обновляется в той же транзакции.
5. **Время** хранится в UTC, отображается и считается в бизнес-логике в `Europe/Moscow`.
6. **Вебхуки** (Точка, СДЭК, Telegram) идемпотентны и проверяют подпись.
7. Вся бизнес-логика цен, скидок, баллов и остатков живёт в `domain/` и покрыта unit-тестами
   (включая граничные случаи) **до** подключения к API.
8. **Все тексты интерфейса — на русском.** В админке: никакого технического жаргона, у каждого неочевидного поля — подсказка.
9. **На витрине запрещены всплывающие окна** (маркетинговые модалки, попапы подписки, автооткрывающиеся чаты).
   Модалка допустима только как прямой ответ на действие пользователя (например, увеличение фото).
10. Секреты — только в переменных окружения; `.env.example` поддерживать в актуальном виде.
11. Персональные данные клиентов хранятся только на серверах в РФ (152-ФЗ).
12. Удаление в админке — мягкое (архив), кроме явной очистки. Каждое действие сотрудника пишется в `AuditLog`.

## Как работать

- Перед задачей перечитай нужный раздел `SPEC.md`. Если требование неоднозначно — спроси, не додумывай.
- Принятые по ходу решения (выбор библиотеки, трактовка требования) записывай в `docs/DECISIONS.md`: дата, решение, причина.
- Новые зависимости — только если без них заметно сложнее; обоснование в `DECISIONS.md`.
- Перед завершением задачи: линтеры, типы, тесты должны проходить.
  - backend: `ruff check`, `ruff format --check`, `mypy`, `pytest`
  - frontend: `pnpm lint`, `pnpm typecheck`, `pnpm test`
- Миграции Alembic — на каждое изменение схемы, с понятным именем.
- Админку проверяй на ширине 375px (телефон) и 1440px (ноутбук).
- Для интеграций используй песочницы/тестовые режимы; боевые ключи никогда не попадают в код и тесты.
